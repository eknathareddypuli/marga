The method

Step Action
1 Write the symptom: who, what, since when
2 Ask what changed
3 Bisect the request path
4 One hypothesis, one test, one note
5 Mitigate, then find the cause

Pod status to next command

Status Next command

CrashLoopBackOff kubectl logs --previous

Gateway errors

Code Suggests

Handy commands

kubectl describe pod POD -n NAMESPACE
kubectl logs POD -n NAMESPACE --previous
kubectl exec POD -- cat /etc/resolv.conf
kubectl get events -n NAMESPACE --sort-by=.lastTimestamp
kubectl get endpoints SERVICE -n NAMESPACE
kubectl describe node NODE

Watch out for

Warning

Change one thing at a time, otherwise no result can be interpreted.

Warning

Save logs and a heap dump before you restart, because the restart removes the evidence.

Warning

Do not edit the identity policy when an organisation level deny is the cause.

Warning

Retrying immediately after throttling makes the throttling worse.
