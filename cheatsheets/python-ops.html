Retry rules

Case Action
429 Wait for Retry-After
5xx or timeout Backoff with jitter
4xx other Do not retry
POST Use an idempotency key

Watch out for

Warning

Never run a script that deletes resources without a dry run and a limit on the count.

Warning

Unpinned dependencies make the same script behave differently next month.

Warning

Catching every exception hides failures, so catch only what you can handle.

Warning

A retry loop without backoff and jitter makes throttling worse.
