"Service debugging order, node commands, DNS settings and network policy reminders."

Check order for a failing Service

Step Command
Service and selector kubectl get svc NAME -o wide
Endpoints kubectl get endpointslices -l kubernetes.io/service-name=NAME
Pod labels and readiness kubectl get pods --show-labels
Direct pod IP kubectl exec POD -- curl -s POD_IP:PORT
DNS kubectl exec POD -- nslookup NAME
Policies kubectl get networkpolicy -A

On the node

Job Command
kube-proxy mode `kubectl -n kube-system logs ds/kube-proxy
iptables rules for a Service `iptables -t nat -S
Conntrack entries `conntrack -L
MTU ip link show

DNS

Setting Effect
ndots:5 Short names try search domains first
Trailing dot Skips the search list
NodeLocal DNSCache Cache per node, fewer conntrack entries

Policy reminders

Rule Why
Policies are additive There are no deny rules
Allow DNS with default deny egress Otherwise names fail
Same list item means AND Separate items mean OR

Watch out for

Warning

A NetworkPolicy that selects a pod makes everything else denied for that direction, so add DNS egress.

Warning

Service selectors that match nothing create an endpoint list that is empty, not an error.

Warning

Changing ndots or DNS config on a busy cluster can create new failures, so test on one workload first.

Warning

Overlapping pod and service CIDRs cause routing problems that are hard to see.
